# Overlay spike: top-layer popovers and dialogs (2026-10-31)

Validates the decision "Overlays use the browser top layer, not a portal" (`authoring/decisions.md`, Overlays, composition and shared code) before the first wave 3 contract. Prototypes: `examples/spike-overlays/` (page `/spike-overlays/`, self-contained preview `dist/previews/spike-overlays.html`, review artifact https://claude.ai/artifact/QmrF4bhYNpK5XzFfoLLBMa). Module under test: `packages/svelte/src/lib/overlay/` (`floating`, `modal`, `overlay.css`). Checks: `tests/browser/spike-overlays.spec.ts`, 10 tests (5 facts × 2 positioning engines), passing in Chromium 153 (`npx playwright test tests/browser/spike-overlays.spec.ts`).

## Verified

| Fact | Evidence |
| --- | --- |
| An overlay inherits the theme of the subtree that opens it, with no portal and no attribute copy | Popover, dialog and Bits UI popover opened from a `data-ggb-appearance="dark"` panel paint `color.surface.overlay` and `color.elevation.border` of the dark context; a Button inside a popover opened from a `brick` compact panel paints the brick accent at the compact height |
| Nested overlays stack in opening order; Escape closes the innermost first | A popover opened inside a modal dialog hits first at `elementFromPoint`; Escape closes it and leaves the dialog, a second Escape closes the dialog |
| A portal-free overlay escapes a clipping, transformed, scrolling container and follows its anchor | Popover opened from inside `overflow: hidden; transform` lies outside the container and moves when the container scrolls |
| Light dismiss, Escape, inert background, focus trap and focus return come from the platform | A press outside closes an `auto` popover; focus lands inside the modal dialog and returns to its trigger on close; `::backdrop` paints `color.surface.scrim` |
| CSS anchor positioning places and flips popovers; the measured fallback does the same | Sides and alignments honored; a popover near the viewport bottom flips above its trigger; both engines pass (`?positioning=measured` forces the fallback) |
| Bits UI coexists: `Popover.ContentStatic` with `popover="manual"` placed by the same attachment | Roles and dismissal come from Bits UI, position and theme from ggbrick; Escape closes and unmounts it |
| Motion is CSS only | `@starting-style` entry, `allow-discrete` exit, `motion.distance.*`, `motion.duration.*`, enter and exit easings; reduced motion removes the translate |

## Learned (now in the module)

- Write `popover` in the markup, not from script: an element rendered without it is displayed for a frame and then plays its exit transition when the attribute arrives.
- Closed overlays need an explicit `display: none` in author CSS: a component's `display: grid` outranks the browser's own rule.
- The reset of the browser popover and dialog styles sits at zero specificity (`:where()`), so that a component's surface, border and radius win in the same cascade layer; a modal dialog keeps `inset: 0; margin: auto` to stay centered.
- Bits UI unmounts its content as soon as `open` is false, so content it owns has no exit transition; a ggbrick overlay primitive keeps the element and lets the browser transition it.

## Not verified here

- Firefox and WebKit: CSS anchor positioning support and the `closedby` attribute; the measured fallback and the backdrop-press fallback exist for them but ran only in Chromium (no WebKit or Firefox project yet, audit B7).
- Tooltips (hover and focus timing, `popover="hint"`), menus with typeahead and submenus, and the focus policy on open for non-modal popovers (`autofocus` inside the content versus focus kept on the trigger): first wave 3 contracts.
- Screen readers: the native semantics are standard, but no assistive-technology test exists.

## Recommendation

Keep the decision. Next steps: Firefox and WebKit smoke projects before the first overlay implementation gate; `motion.distance.*` confirmed at the tokens gate; the first wave 3 contracts (Popover, Dialog, Tooltip, Menu) reference `lib/overlay` under `dependencies`.

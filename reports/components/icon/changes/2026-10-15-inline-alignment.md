# Change record — Icon inline alignment

- Request and scope: the user noticed on the documentation site (2026-10-15) that an icon placed next to text, outside a Button, sits low (“✓ Changes saved”, “Invoice 1042 ✓”). Fix the alignment of the Icon next to text; nothing else.
- Starting source/output references: contract digest 159c7201… (approved 2026-10-14), `icon.css` digest 16a5dc6e… (`vertical-align: middle`).
- Affected components, dependencies and contexts: Icon standalone next to text, in every brand, appearance and density. Not affected: the Button (its slots are inline-flex boxes and the icon is `display: block` there), the Counter and the Shortcut (no icon).
- Compatibility and reason: compatible. Same API and box; an inline icon moves up by 1.1 to 1.8 px. `vertical-align: middle` centers a box on the parent's x-height, below the middle of the capitals.
- Source decisions and target-only adaptations: contract rule added: “Next to text, outside a host that places it, the box is centered on the cap height of the surrounding text (the middle of its capitals), not on its x-height or its line box.” Svelte: `vertical-align: calc((1cap - var(--ggb-icon-size)) / 2)`, with `middle` kept as the fallback for browsers without the `cap` unit. Figma: the master is the box alone and does not change; a frame that places an icon next to a text layer centers it on the text box (auto layout), and matches the code when the text layer uses a cap-height leading trim.
- Changed artifacts: `foundations/components/content/icon/contract.json`, `packages/svelte/src/components/icon/icon.css`, `documentation/components/icon.md` (Anatomy), `tests/browser/icon.spec.ts`, review screenshots in `reports/components/icon/svelte/`.
- Approvals retained or reopened, with provenance: contract and implementation approvals reopened for this amendment (new digests in `status.json`, `pendingChanges`); Figma parity retained (masters unchanged); documentation follows.
- Checks performed and evidence: offset of the icon center from the middle of the capitals on the review page (“Inline with every text size”): before 1.64, 1.45, 1.08, 1.82 px (md on body lg, sm on body md, xs on caption, lg on heading md); after ≤ 0.02 px. New browser test `next to text, the box is centered on the cap height of the surrounding text` (tolerance 0.5 px); full suite 40 passed; `npm run verify`.
- Remaining limitations: a browser without the `cap` unit (before Chrome 118, Safari 17.2, Firefox 97) keeps the previous `middle` alignment.

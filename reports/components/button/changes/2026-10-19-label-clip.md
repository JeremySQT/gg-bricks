# Change record — Button label clip

- Request and scope: at the implementation review of IconButton, Link and Badge (2026-10-17), the user saw Badge descenders cut; the cause (a vertical clip on the cap-trimmed label, relaxed only by `overflow-clip-margin`, which Safari does not support) is shared with the Button label. The user authorized the same fix on the Button on 2026-10-19, "si ça n'impacte pas l'alignement vertical". Scope: `button.css`, label clip only.
- Starting source/output references: `button.css` as approved (implementation approval re-recorded 2026-10-14); label `overflow: clip; overflow-clip-margin: 0.3em` with `text-box: trim-both cap alphabetic`.
- Affected components, dependencies and contexts: Button label in every brand, appearance, density and size, in browsers that support `text-box` but not `overflow-clip-margin` (Safari). IconButton has no label; Badge received the same fix in its own implementation.
- Compatibility and reason: compatible. Same API, layout and geometry. The label is now clipped in the inline direction only (`overflow-x: clip; overflow-y: visible`): the ellipsis needs nothing more, and descenders and accents extend past the trimmed box in every browser.
- Source decisions and target-only adaptations: no contract change (the contract already requires "descenders and accents stay visible"); target-only CSS.
- Changed artifacts: `packages/svelte/src/components/button/button.css`, review screenshots in `reports/components/button/svelte/`.
- Approvals retained or reopened, with provenance: implementation approval re-recorded with the new `button.css` digest on the user's conditional authorization, the condition being verified below; contract, Figma parity and documentation retained (no rendering change in Chromium, no API change).
- Checks performed and evidence: geometry of the 66 Buttons of the review page in 3 densities (container size, label, leading and trailing boxes relative to the container) before and after the fix: 198 measurements, 0 differences at 0.001 px. `reports/components/button/svelte/computed.json` byte-identical after the browser test. Button browser tests (9, including cap-height ink centering and tight ellipsis) pass; full suite and `npm run verify` pass.
- Remaining limitations: not verified in WebKit (not installed in this environment); the reasoning relies on Safari's documented lack of `overflow-clip-margin`.

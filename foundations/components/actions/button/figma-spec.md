## Construction notes

- **Root** reserves the 44px interaction height (`size/target/min`) around the container; the container keeps the size height.
- **Container** padding is `space/control/edge-inline/{size}` and `space/control/padding-block/{size}`; **Label** carries `space/control/label-inline/{size}` on both sides; **Leading** and **Trailing** carry `space/control/slot-inline/{size}`.
- **Optical icon spacing**: icons sit in a _Drawing box_ sized to the icon's drawing (iconSize × 3/4), so the box overlaps the slot spacing by 1/8 of the icon size on each side, like the CSS negative margin. The compensation belongs to Button (Leading, and Type=Icon of `_Button/Trailing`); the icon component itself stays neutral.
- **Trailing**: one frame carrying the slot margin, holding an exposed instance of the internal `_Button/Trailing` set (same page), Type only (3 variants since 2026-10-26; Type × Size before), each holding only its own content: Icon (drawing box with the Phosphor glyph itself behind the part's Icon property, placed by its drawing; an Icon instance until 2026-10-26), Counter and Shortcut (the internal parts `_Counter/Nested` and `_Shortcut/Nested`, placed by their box). The Counter and Shortcut masters carry their size as a variant for use on their own; their nested parts take the size from the Components mode the Button variant sets, so nothing in the trailing item has a Size a designer could change (user decision, 2026-10-26). The drawing box centers the icon with auto layout: the part is shared by the three sizes through modes, so an absolute position would be right for one size only (it left the icon 2 px low in md and 4 px in lg before 2026-10-12).
- **Slot color**: slot content (the glyph vector of the leading and trailing Icon, the Counter's Value fill and Tint fill, the Shortcut's key and separator texts) is bound to `button/foreground` by nested overrides of the instances, which resolves to the content color of the variant's intent, appearance and state through the modes each variant sets (see Adapter mechanics), like `currentColor` in the code. No per-variant color override is needed, so switching Type or Name keeps the right color.
- **Cap-height centering**: the label text uses vertical trim (leading trim to cap height), the Figma equivalent of `text-box: trim-both cap alphabetic`.
- **Loading**: the Loading indicator is centered over the container (absolute); Leading, Label and Trailing are kept in the layout at opacity 0, so the width does not change. Since 2026-11-03 the Loading indicator is an instance of the **Spinner** set (`408:15`, feedback/spinner) of the icon size, its two strokes in the variant's content color (it was the internal part `_Button/Loading indicator` 42:28, removed; `authoring/adapters/figma/button-spinner-swap.plugin.js`).
- **Outline appearance**: the border is an inside stroke bound to the border role, so it never changes outer dimensions (`strokesIncludedInLayout` off on containers).
- **Focus ring**: absolute frame 2px outside the container (the focus offset), outside stroke bound to `focus/width` and `color/focus/ring`, corner radius bound to `radius/focus` (radius.control + focus.offset, so the ring stays concentric with the container, as the CSS outline renders it).

## Justified differences

Recorded as such in `parity.json`; none hides a defect of the masters.

1. **Forced-colors outline.** The code keeps a transparent 1px outline so that forced-colors mode draws a boundary. Figma has no forced-colors mode: no layer stands for it (594 `outline` records noted as justified).
2. **Focus ring corner.** Resolved on 2026-10-13: the ring corner is bound to the new `radius/focus` role (8, 4, 14 per brand), equal to what the CSS outline draws. No difference remains.
3. **Focus offset** is ring geometry (2px), not a variable binding, because Figma cannot bind an absolute position. `focus/offset` is 2 in every brand and density.
4. **Loading + focus.** The browser measurement keeps focus on a loading button (loading stays focusable), so its focus outline is computed; in Figma the State=loading variant combines with the separate Focus boolean (shown in States). 36 records noted as justified.
5. **Disabled + loading** is an instance override in the specification (State=disabled, Loading indicator visible, content at opacity 0), not a variant: it is a rare combination and would add 27 variants.
6. **Width.** Figma rounds the text layer to whole pixels and rasterizes Inter slightly differently: widths differ from the browser by 0.13 to 1.06px; parity tolerance ±1.5px. Heights, paddings and margins match exactly.
7. **Tight ellipsis.** The code ends the visible box at the ellipsis and keeps the full label as accessible name. Figma truncates the text layer (ellipsis at the end): for a constrained width, set the instance width to Fixed or Fill and set Container, Label and Text to Fill (example in Behavior & sizing).
8. **Horizontal 44px target.** The code also reserves 44px horizontally for very short labels; the Figma root reserves the height only.
9. **Spinner rotation, color transitions and reduced motion** are code-only.
10. **Icon glyphs.** The slots hold the Icon component, whose glyphs are the local Phosphor 2.1.1 regular components of the page `assets/phosphor` (since 2026-10-19; before, five `_Fixture/Icon` glyphs with the same drawings). Counter and Shortcut are the real components since 2026-10-14; no fixture remains. The glyph color is a nested override (`button/foreground`): Figma drops it when an instance swap replaces the nested glyph through a default change (the 2026-10-19 migration did so on the 135 leading icons; restored the same day) or when the default glyph is re-selected explicitly; choosing another glyph or resetting the instance restores it.

## Page style and diagrams

The page sits on a light gray background. A white header holds the breadcrumb, the title, the summary, a hero card (near-white surface, 8 px white border, soft shadow), the reference note and, after a divider, the Anatomy section. The body shows each section as a bullet heading with its text, then white cards with a light border; the dark states block and the dark context cards keep the system's dark canvas. The user tuned this layout by hand on 2026-10-13 and the builder script reproduces it.

The Anatomy section shows a structure diagram (root, container, leading, label, trailing, loading indicator, focus ring, numbered callouts joined to the parts by dashed leader lines) and a spacing diagram zoomed in four times (edge padding, label margin, slot margin, icon drawing versus icon box, as dimension lines). Both are blueprint boards presented as cards: a blue/800 background with a white 16 px grid at 10% opacity, white ink and translucent white tints with dashed outlines, a white 8 px border and a soft shadow, so they read as a schematic rather than as the real component. Colors come from the Figma-only **Wireframe** collection (hidden from publishing, like the Components adapter collections), which has two modes: `light` (page default, used by legends, callouts and cards) and `blueprint` (set explicitly on the boards); the recurring pieces are the documentation components `_Spec/Board`, `_Spec/Callout` and `_Spec/Marker` on the Utilities page. The structure diagram is not to scale: the root is drawn taller than it is, otherwise its outline merges with the focus ring; the focus ring is drawn with a corner radius of container radius plus offset, as the CSS outline renders it and as `radius.focus` records. None of this is a source token or part of the library API.

## Adapter mechanics

- Collection **Components** (hidden, modes sm, md, lg; each Button variant sets the mode of its Size) holds `button/icon-drawing` = 12, 15, 18, the optical drawing box (3/4 of `size/icon/{size}`, because Figma cannot compute a fraction of a variable), and `button/icon-size`, an alias of `size/icon/{size}`, next to the `counter/…` and `shortcut/…` adapter variables of the other components (regrouped from the former `_ggbrick button size` collection on 2026-10-14). The modes let the shared `_Button/Trailing` part size its icon without a Size property. These are not source tokens, contract fields or code requirements.
- Collections **Components · button style** (9 modes, one per intent-appearance pair) and **Components · button state** (modes default, hover, pressed, loading, disabled; both hidden, renamed from `_ggbrick button style` and `_ggbrick button state` on 2026-10-14) hold `button/foreground` and its nine per-pair variables, aliases of `color/action/{intent}/{appearance}/{state}/content`. Each Button variant sets its style and state modes. They stay separate because the shared trailing part needs two independent mode axes: one collection would need 45 modes.
- The Shortcut inside a button keeps its Plain attenuation (`opacity/muted`), as the code does.
- Native Figma slots: the Plugin API accepts a SLOT property with preferred components but cannot create or bind the slot layer, so the internal part is used instead; to revisit when the API supports it.
- `figma.skipInvisibleInstanceChildren = false` is required when scripts read hidden slot layers of instances.

## Parity method

Slot geometry is measured separately (`button-parity-slots.plugin.js`): in every context and size, with a trailing icon and with a counter (the Counter component since 2026-10-14), the leading drawing must sit at edge + slot from the container edge and slot + label from the label text, the trailing item symmetrically, and icons must be centered vertically at the icon size. The report lists these 108 records under `slotGeometry`.

For each of the 18 contexts (brand × appearance × density) a temporary frame with explicit modes holds instances of the 27 default cases (label Continue or Delete, leading icon on md) and, in base-light-standard, base-dark-standard, brick-light-compact and orchid-dark-comfortable, the 45 md state cases (label "Save changes"). Bound variables are resolved with `resolveForConsumer`, geometry is read from the laid-out instances, the frame is removed, and each value is compared with the matching record of `reports/components/button/svelte/computed.json`.

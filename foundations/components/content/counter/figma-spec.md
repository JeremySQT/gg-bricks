## Construction notes

- **Container**: horizontal auto layout, hug width, fixed height bound to `typography/indicator/{size}/lineHeight` (the line box), `minWidth` bound to the same variable (minimum width equal to the height: Figma cannot derive one from the other), content centered on both axes, no fill, no clipping.
- **Value**: text layer, Inter Medium through the text style, auto width and height, centered. Figma rounds its auto height to whole pixels (16, 17, 20 for 15.4, 16.8, 19.6), so the container height is bound to the line-height variable instead of hugging the text; the layer sits centered and overflows the box by 0.3 px at most, which does not render.
- **Border**: a stroke-only rectangle, absolutely positioned at (0, 0) with the size of the box and **SCALE** constraints, inside stroke. STRETCH constraints round the master's fractional width when they are applied to an instance (a 19 px instance got a 19.4 px border); SCALE keeps the border equal to the box in every instance, including when the Value text changes. Its layer opacity carries the 70 % attenuation so that the digits keep their full opacity: a paint opacity cannot bind a variable.
- **Default variant**: Figma takes the top-left variant of the set as the default, whatever the child order, so the md row is placed first (rows md, sm, lg; columns Overflow false, true), with a 40 px margin.
- **Set description** names the purpose, the contract and the implementation folder, the meaning of Size, Overflow, Overflow text and Value, and that the counter is not interactive.

## Justified differences

Recorded as such in `parity.json`; none hides a defect of the masters.

1. **Tabular figures.** The code sets `font-feature-settings: "tnum"`. The Plugin API cannot set OpenType features (`openTypeFeatures` is read-only, like for the text styles, see `reports/tokens/figma/ledger.json`), and Inter's default figures in Figma are proportional (at md, 11 is 12 px wide and 88 is 16 px). The measured values (8 and 99+) contain no narrow digit, so widths match; a counter showing 1 or 11 would be narrower in Figma than in the browser until tabular figures are switched on by hand (Type settings → Numbers → Tabular) on the three `typography/indicator` text styles (which also serves the Shortcut) or on the six Value layers. 108 records noted as justified.
2. **Border opacity binding.** Figma reads a number bound to layer opacity as a percentage: binding `opacity/muted` at 0.7 rendered the border at 0.7 %. Since 2026-10-14 the token sync emits opacity variables ×100 for Figma (`opacity/muted` = 70, `packages/tokens/figma-manifest.json` and expectations follow), so the Border binds `opacity/muted` directly; the temporary mirror variable `counter/border-opacity` was removed. The effective opacity is 0.7 in every context (parity records on `box-shadow`).
3. **Inside a Button.** The 72 computed records measured inside Buttons (9 intent × appearance pairs in 4 contexts) are compared with the resolution of `button/foreground`, the adapter variable the Button binds its slot content to, with the style mode of the pair and the default state mode: this is the binding the orchestrator will apply to the Counter instance inside the Button. Noted as proxy records (`summary.hostProxy`), 0 failures.
4. **Width.** Figma rounds the text layer width to whole pixels and rasterizes Inter slightly differently: widths differ from the browser by −0.14 to 0.78 px; parity tolerance ±1.5 px. Heights, minimum widths, paddings, radii, stroke widths, colors and typography match exactly (the browser lays the 15.4 px line box out as 15.390625 px in 1/64 px units: tolerance 0.05 px on `block-size` and `min-inline-size`).
5. **Forced colors**, the hidden accessible label and the locale-dependent digit grouping are code-only; no layer stands for them.
6. **Overflow as a variant.** The contract's derived state is a boolean-valued variant property rather than a boolean component property: a boolean property can only show or hide layers and cannot swap the Value text for the capped text. Figma shows it as a switch, so the designer experience is the one of a boolean.

## Adapter mechanics

- Collection `_ggbrick counter` (hidden from publishing, one mode) holds `counter/foreground` (COLOR, scopes TEXT_FILL and STROKE_COLOR, hidden, alias of `color/content/primary`), bound to the Value fill and the Border stroke: it stands for the inherited content color (`currentColor` in the code). Standalone, the counter resolves to the primary content color of the appearance; inside the Button the orchestrator overrides both bindings of the instance with `button/foreground`, which resolves to the content color of the button's intent, appearance and state through the Button's modes.
- The adapter variable is not a source token, a contract field or a code requirement. Opacity variables reach Figma in percent (adapter convention of the token sync, see `authoring/figma.md`).
- `figma.skipInvisibleInstanceChildren = false` is set by every script that reads instance children.

## Parity method

For each of the 18 contexts (brand × appearance × density) a temporary frame with explicit Brand, Appearance and Density modes holds one instance of each of the six variants (Value 8, Overflow text 99+). Bound variables are resolved with `resolveForConsumer`, the effective Border opacity and the laid-out geometry are read from the instances, the frame is removed, and each value is compared with the matching record of `reports/components/counter/svelte/computed.json` (`authoring/adapters/figma/counter-parity.plugin.js`, then `counter-parity-report.mjs`). The 72 records inside Buttons are compared with `button/foreground` resolved per intent × appearance pair in the four representative contexts (proxy). Inter's default figure widths (00, 11, 88, 10) are measured in the same run to document the tabular-figures limitation.

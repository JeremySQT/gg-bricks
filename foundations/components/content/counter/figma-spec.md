## Construction notes

- **Container**: horizontal auto layout, hug width, fixed height bound to `typography/indicator/{size}/lineHeight` (the line box), `minWidth` bound to the same variable (minimum width equal to the height: Figma cannot derive one from the other), content centered on both axes, no fill, no clipping.
- **Value**: text layer, Inter Medium, auto width and height, centered, leading trim set to cap height (the digits' box is their cap height: 8, 9, 10 px for sm, md, lg) so the auto layout centers the ink in the line box, as the code's `text-box: trim-both cap alphabetic` with symmetric block padding does. The container height is bound to the line-height variable (Figma rounds an untrimmed text layer's height to whole pixels, and the trimmed one is shorter than the line box). Leading trim is a text-style property, so setting it on the node detached the `typography/indicator/{size}` style the builder applies; the node keeps the five typography bindings and the fill binding, which is what the parity checks (the Button labels and the Shortcut keys bind the same way, without a style).
- **Tint**: a filled rectangle (fill bound to `counter/foreground`, no stroke), absolutely positioned at (0, 0) with the size of the box and **SCALE** constraints, under the digits. STRETCH constraints round the master's fractional width when they are applied to an instance (a 19 px instance got a 19.4 px layer); SCALE keeps the tint equal to the box in every instance, including when the Value text changes. Its layer opacity carries the 12 % attenuation (`opacity/tint`) so that the digits keep their full opacity: a paint opacity cannot bind a variable. Until 2026-10-14 this layer was a stroke-only **Border** at 70 % (`opacity/muted`, `border/width/default`); the user chose the tint on the implementation review page and the layer was converted in place (same node IDs).
- **Default variant**: Figma takes the top-left variant of the set as the default, whatever the child order, so the md row is placed first (rows md, sm, lg; columns Overflow false, true), with a 40 px margin.
- **Set description** names the purpose, the contract and the implementation folder, the meaning of Size, Overflow, Overflow text and Value, and that the counter is not interactive.

## Justified differences

Recorded as such in `parity.json`; none hides a defect of the masters.

1. **Tabular figures.** The code sets `font-feature-settings: "tnum"`. The Plugin API cannot set OpenType features (`openTypeFeatures` is read-only). The user switched tabular figures on by hand on the three `typography/indicator` text styles on 2026-10-14; the sm and md Value layers read `tnum`, the lg ones read the default (the style was detached by the leading trim, see Construction notes), and the measured widths of 00, 11, 88 and 10 at md are all 16 px, so Inter's figures render tabular in the file. 36 records (lg) noted as justified.
2. **Tint opacity binding.** Figma reads a number bound to layer opacity as a percentage: binding an opacity at 0.7 rendered the former border at 0.7 %. Since 2026-10-14 the token sync emits opacity variables ×100 for Figma (`opacity/tint` = 12, `packages/tokens/figma-manifest.json` and expectations follow), so the Tint binds `opacity/tint` directly. The effective opacity is 0.12 in every context (parity records on `background-color`: the code paints `rgb(from currentColor r g b / surfaceOpacity)`, Figma a layer in the content color at that opacity).
3. **Block padding.** The code centers the cap-trimmed digits with a symmetric block padding of (line box − cap height) / 2; Figma centers the cap-trimmed Value in the fixed-height container with no padding: the same geometry (108 records on `padding-block` noted as justified).
4. **Inside a Button.** The 72 computed records measured inside Buttons (9 intent × appearance pairs in 4 contexts) are compared with the resolution of `button/foreground`, the adapter variable the Button binds its slot content to, with the style mode of the pair and the default state mode: this is the binding the orchestrator will apply to the Counter instance inside the Button. Noted as proxy records (`summary.hostProxy`), 0 failures.
5. **Width.** Figma rounds the text layer width to whole pixels and rasterizes Inter slightly differently: widths differ from the browser by −0.14 to 0.78 px; parity tolerance ±1.5 px. Heights, minimum widths, paddings, radii, opacity, colors and typography match exactly (the browser lays the 15.4 px line box out as 15.390625 px in 1/64 px units: tolerance 0.05 px on `block-size` and `min-inline-size`).
6. **Forced colors** (the `borderWidth` edge drawn only under `forced-colors: active`), the hidden accessible label and the locale-dependent digit grouping are code-only; no layer stands for them.
7. **Overflow as a variant.** The contract's derived state is a boolean-valued variant property rather than a boolean component property: a boolean property can only show or hide layers and cannot swap the Value text for the capped text. Figma shows it as a switch, so the designer experience is the one of a boolean.

## Adapter mechanics

- The hidden **Components** collection (modes sm, md, lg; one collection for every component adapter variable since 2026-10-14, formerly `_ggbrick counter`) holds `counter/foreground` (COLOR, scopes TEXT_FILL and SHAPE_FILL, hidden, alias of `color/content/primary` in the three modes), bound to the Value fill and the Tint fill: it stands for the inherited content color (`currentColor` in the code). Standalone, the counter resolves to the primary content color of the appearance; inside the Button the orchestrator overrides both bindings of the instance with `button/foreground`, which resolves to the content color of the button's intent, appearance and state through the Button's modes.
- The adapter variable is not a source token, a contract field or a code requirement. Opacity variables reach Figma in percent (adapter convention of the token sync, see `authoring/figma.md`).
- `figma.skipInvisibleInstanceChildren = false` is set by every script that reads instance children.

## Parity method

For each of the 18 contexts (brand × appearance × density) a temporary frame with explicit Brand, Appearance and Density modes holds one instance of each of the six variants (Value 8, Overflow text 99+). Bound variables are resolved with `resolveForConsumer`, the effective Tint opacity, the Value leading trim and the laid-out geometry are read from the instances (the line height from the node's effective value, in pixels), the frame is removed, and each value is compared with the matching record of `reports/components/counter/svelte/computed.json` (`authoring/adapters/figma/counter-parity.plugin.js`, then `counter-parity-report.mjs`). The 72 records inside Buttons are compared with `button/foreground` resolved per intent × appearance pair in the four representative contexts (proxy). Inter's default figure widths (00, 11, 88, 10) are measured in the same run to document the tabular-figures limitation.

## Construction notes

- **\_Shortcut/Key**: an auto-layout frame holding one text layer. The text binds `fontSize`, `lineHeight` and `letterSpacing` to the `shortcut/…` adapter variables of the Components collection and its fill to `shortcut/foreground`. Plain has no fill, stroke, padding or minimum width. Keycap binds its fill to `color/surface/subtle`, its inside stroke to `color/border/default` with weight `border/width/default`, its four corners to `radius/control`, its left and right padding to `space/content/xs` (no block padding) and its minimum width to `shortcut/cap-min-width`; `strokesIncludedInLayout` is on, so the stroke counts in the layout like a border-box border: the cap is the text line plus two borders tall and the padding sits inside the border, as in the code.
- **\_Shortcut/Separator**: a frame holding a “+” text bound like the key text.
- **Shortcut variants**: an auto-layout row (center aligned, no fill) that sets the Components mode of its Size. Keycap variants bind the gap to `space/content/xs`; Plain variants have a 0 gap and bind their opacity to `opacity/muted` (synced in percent, see Justified differences 3). Mac variants hold Key 1, Key 2, Key 3 (⌘, K, K); Other variants hold Key 1, Separator 1, Key 2, Separator 2, Key 3 (Ctrl, +, K, +, K). Key 3 and Separator 2 are hidden by default (Show key 3); Key 2 and Separator 1 follow Show key 2.
- **Default variant**: Figma takes the top-left variant of the set as the default, so the grid's first column is md (then sm, lg) and the first row is Plain · Mac: the contract defaults (plain, md) plus Mac.
- **Descriptions**: the three component sets carry their purpose, the source of truth and the implementation path.

## Justified differences

Recorded as such in `parity.json`; none hides a defect of the masters.

1. **Line box rounding.** Figma rounds an auto-sized text layer to whole pixels: line heights 15.4, 16.8 and 19.6 give layers 16, 17 and 20 px tall, so plain keys and caps are 0.2 to 0.6 px taller than in the browser (17.39 → 18, 18.8 → 19, 21.59 → 22). Tolerance ±1 px on heights; 216 records.
2. **Square minimum.** The code uses `calc(1lh + 2 × borderWidth)` (17.39, 18.8, 21.59). Figma cannot add two variables, and with the rounded line boxes a cap of that minimum would be narrower than tall, so the adapter variable `shortcut/cap-min-width` holds the rounded line box plus two borders (18, 19, 22; `border/width/default` is 1 in every brand). Delta 0.2 to 0.6 px; 108 records. If a brand ever changed its default border width, this variable would need an update.
3. **Opacity as a percentage.** Figma reads a number variable bound to layer opacity as a percentage, so `opacity/muted` at 0.7 bound directly rendered at 0.7 %. Since 2026-10-14 the token sync emits opacity variables ×100 for Figma (`opacity/muted` = 70), so the Plain variants bind `opacity/muted` directly; the temporary mirror variable `shortcut/plain-opacity` was removed. The effective opacity is 0.7 in every context (216 opacity records).
4. **OpenType features.** `font-feature-settings: "tnum"` cannot be set through the Plugin API (text style description records it); the keys show letters and glyphs, not figures. 216 records.
5. **Widths.** Figma rounds the text layer to whole pixels and rasterizes Inter slightly differently: the first key is 0.20 to 0.98 px wider than in the browser; parity tolerance ±1.5 px. Paddings, gaps, radii and stroke widths match exactly.
6. **Inherited color.** The code inherits `currentColor`; Figma has no inheritance, so the texts bind `shortcut/foreground` (alias of `color/content/primary`). A host rebinds it: the Button binds the key texts and separators of its Shortcut trailing item to `button/foreground` (done on 2026-10-14).
7. **Nested text properties.** The Plugin API refuses component property references on instance sublayers, so a set-level “Key 1” text property cannot drive the nested key text. The nested instances are exposed instead (Key 1, Key 2, Key 3 each show their Key text and, unavoidably, their own Appearance); a designer types the glyph or the short name as the specification table shows.
8. **Three keys.** The master shows up to three keys (two by default). A combination with four or more keys (`Ctrl+Alt+Shift+Meta+Delete`) is rare and is composed from two instances side by side.
9. **Platform auto, the spoken equivalent, `label`, forced-colors mode and the one-paint flip after mount** are code-only.
10. **Fallback glyphs.** ↩ ⎋ ⇥ ⌫ ⌦ ↖ ↘ ⇞ ⇟ are not in Inter; Figma renders them with a system fallback font, as the browser does with its font stack. Their weight and alignment differ slightly from ⌃ ⌥ ⇧ ⌘ and the arrows, which Inter covers.

## Page style and diagrams

The page follows the Button specification: a light gray page, a white header with the breadcrumb, the title, the summary, a hero card (near-white surface, 8 px white border, soft shadow) showing two menu-like rows and two keycap combinations, the reference note and, after a divider, the Anatomy section; the body shows each section as a bullet heading with its text, then white cards with a light border; dark context cards keep the system's dark canvas.

The Anatomy section shows a structure diagram (container, two keys, separator, numbered callouts joined to the parts by dashed leader lines) and a keycap diagram zoomed in eight times (side padding, border, gap, cap height as dimension lines, the text line as a lighter box inside each cap). Both are blueprint boards presented as cards with the Wireframe collection in `blueprint` mode and the documentation components `_Spec/Board` (style reference), `_Spec/Callout` and `_Spec/Marker` on the Utilities page. The Variants section holds the keys table (what you write, what Mac shows, what other platforms show, what screen readers say) built from keycap instances, the modifier order with two examples, and six brand × appearance cards. None of this is a source token or part of the library API.

## Adapter mechanics

- The hidden **Components** collection (modes sm, md, lg; one collection for every component adapter variable since 2026-10-14, formerly `_ggbrick shortcut size` and `_ggbrick shortcut`; each Shortcut variant sets the mode of its Size) holds `shortcut/font-size`, `shortcut/line-height` and `shortcut/letter-spacing`, aliases of `typography/indicator/{size}/fontSize|lineHeight|letterSpacing`, so that `_Shortcut/Key` binds once, plus `shortcut/cap-min-width` (18, 19, 22, see Justified differences 2). The same pattern as the Button's `button/icon-size`.
- `shortcut/foreground` (COLOR, scopes TEXT_FILL and STROKE_COLOR, alias of `color/content/primary` in the three modes, same collection) is bound by the key texts and the separators.
- These are not source tokens, contract fields or code requirements.

## Parity method

For each of the 18 contexts (brand × appearance × density) a temporary frame with explicit modes holds instances of the 12 variants in the three-key form the browser measured (`Mod+Shift+K`: ⇧ ⌘ K on Mac, Ctrl + Shift + K on Other, Show key 3 on). Bound variables are resolved with `resolveForConsumer`, geometry is read from the laid-out first key and first separator, the frame is removed, and each value is compared with the matching record of `reports/components/shortcut/svelte/computed.json` (`shortcut-parity.plugin.js`, one run per brand; `shortcut-parity-report.mjs` writes the report). Opacity is not in `computed.json` (the browser test asserts it separately), so the report carries 216 opacity records from the contract role under `opacity`.

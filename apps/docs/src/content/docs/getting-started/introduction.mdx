ggbrick is a design system delivered as three products that agree with each other because they come from the same sources:

1. **A Figma library**, the validated visual representation, driven by variables generated from the tokens.
2. **Svelte 5 components** (`@ggbrick/svelte`), built on Bits UI for native semantics and keyboard behavior. Install the package or copy a component's folder into your project.
3. **Documentation**, one maintained page per component for people and agents, shipped inside the package and published here with live examples.

The sources of truth are DTCG token files and one compact, platform-independent contract per component. Figma, code and documentation are generated from them or checked against them, and every component carries recorded evidence: contrast in every context, browser tests with axe-core, and a Figma parity report.

## How this site is organized

- **Getting started**: installing the package, setting the theme attributes, copying a component instead of installing, and working with an agent.
- **Foundations**: the tokens every component is built on — color, typography, spacing and sizing, shape, elevation and motion — shown in the brand, appearance and density you select in the header.
- **Components**: one page per component with the same sections everywhere (Overview, When to use, When not to use, Anatomy, Usage guidelines, Examples, API, Accessibility), live examples, and a generated contract and evidence section.

## Status

ggbrick is at version 0.1.0 and not yet published to npm. Components are built in waves; the first wave delivers the Button and the contents of its slots (Icon, Counter and Shortcut). A name marked “planned” in a page is not an export yet.

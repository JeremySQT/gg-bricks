## Requirements

- Svelte 5 (the package is tested with Svelte 5.57.1).
- Bits UI is the only other runtime dependency; the package installs it.

## Install the package

The package is not on npm before the first release. Build a tarball from the repository and install it in your application:

```sh
# in the ggbrick repository
npm ci
npm run pack:svelte          # writes dist/ggbrick-svelte-<version>.tgz

# in your application
npm install /absolute/path/to/ggbrick-svelte-<version>.tgz
```

## Load the tokens and the fonts

Import `tokens.css` once, at the root of the application. It defines every token as a CSS custom property (`--ggb-<path>`) for every brand, appearance and density.

```svelte
<script lang="ts">
  import '@ggbrick/svelte/tokens.css';
</script>
```

Components do not load fonts. ggbrick sets interface text in Inter and code in IBM Plex Mono; load them the way your application loads fonts, for example with Fontsource:

```ts
import '@fontsource/inter/400.css';
import '@fontsource/inter/500.css';
import '@fontsource/inter/600.css';
import '@fontsource/inter/700.css';
import '@fontsource/ibm-plex-mono/400.css';
```

## Keep your global styles off the components

Component styles live in the `ggb` cascade layer, so any rule of your application that is not in a layer wins over them, whatever its specificity: that is how you adjust a component. It also means that a global rule meant for your own elements reaches the components too. The common case is a focus outline: components draw their own focus ring, and a global `:focus-visible { outline: … }` adds a second one. Scope such rules away from them:

```css
:focus-visible:not([class*='ggb-']) {
  outline: 2px solid var(--ggb-color-focus-ring);
}
```

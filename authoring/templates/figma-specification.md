# Component Figma specification

## Overview

Short purpose, status, contract reference and identifiable reviewed revision.

## Anatomy

Annotated parts, slots, accepted contents and optional elements. Match the contract.

## Variants

Show supported options and meaningful combinations. Use boolean properties or instance swaps where appropriate; avoid a Cartesian variant explosion. Distinguish brand/theme/density context from component options.

## States

Show defined states and important combinations. Include cases that can change construction before requesting design approval. Do not infer unavailable states from a generic checklist.

## Behavior & sizing

Explain hug/fill/fixed behavior where supported, alignment, min/max dimensions, overflow and relevant density/viewport adaptations. Annotate applicable token bindings rather than maintaining a parallel hand-entered value source.

## Usage examples

Show realistic compositions and relevant difficult cases: long content, absent optional content, constrained space or asynchronous operation as appropriate. Include key designer-facing guidance; link complete docs instead of copying the target API.

## Preparation and acceptance

Keep masters distinguishable from explanatory instances. Before design approval, explore material states and edge cases. Before implementation readiness, finalize annotations and reconcile contract changes.

Record file/node references, scope and review evidence in the component status. Exact page layout/naming is still to be standardized. Use current Figma tool guidance and inspect the destination before writing.
